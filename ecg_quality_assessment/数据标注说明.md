**状态**: 已修复，现在使用真实标注

**标注文件**: `data/raw/challenge-2011/set-b/*.txt`

**标注格式**:
- 每个记录有一个对应的`.txt`文件
- 每行代表1秒的数据
- 格式: `时间戳,导联1评分,导联2评分,...,导联12评分`
- 质量评分规则:
  - **可接受**: 评分值较小（通常 < 50）
  - **不可接受**: 评分值较大（通常 > 50）或异常值

**代码修改**:
1. ✅ 更新 `config.py`: 路径指向 `set-b` 目录
2. ✅ 更新 `utils/data_loader.py`: 新增 `load_annotation()` 和 `load_all_records_with_labels()` 方法
3. ✅ 更新 `prepare_data.py`: 使用真实标注而非模拟标签

**标签分配策略**:
- Challenge 2011的记录是10秒长，每秒有一个质量标注
- 将其分割为5秒片段
- **规则**: 如果5秒内有任何1秒被标记为不可接受，则整个5秒片段标记为不可接受

## 🔍 故障排除

### 问题1: 没有找到标注文件

**症状**:
```
警告：未找到标注文件 XXX.txt，跳过此记录
```

**解决方案**:
1. 检查 `data/raw/challenge-2011/set-b/` 目录
2. 确认每个`.hea`文件都有对应的`.txt`文件
3. 确认文件名匹配（如 `1000066.hea` 对应 `1000066.txt`）

### 问题2: 标注解析失败

**症状**:
```
警告：解析标注文件 XXX.txt 失败: ...
```

**解决方案**:
1. 检查`.txt`文件格式是否正确（逗号分隔）
2. 确认文件编码（应为UTF-8或ASCII）
3. 查看报错信息，确定具体问题

### 问题3: 标签比例不合理

**症状**: 干净/含噪比例与论文差异很大

**可能原因**:
1. 标注阈值设置不当（代码中是50）
2. 标签分配策略过于严格或宽松

**解决方案**:
调整 `utils/data_loader.py` 中的阈值：

```python
# 在 load_annotation 方法中
# 当前阈值: 50
is_unacceptable = all(abs(score) > 50 for score in lead_scores)

# 可以尝试调整为其他值，如:
is_unacceptable = all(abs(score) > 40 for score in lead_scores)  # 更严格
is_unacceptable = all(abs(score) > 60 for score in lead_scores)  # 更宽松
```
